# 遠回りメモ

量子回路をシミュレーションする、ちょっと遠回りなメモ帳。

計算は端末内で行い、量子コンピュータは使用しません。タイトルを選び、「量子検索」で本文を開きます。普通なら簡単に済む操作を、量子回路のシミュレーションで少し遠回りするメモ帳です。

## 使い方

一覧下部の「ヘルプ」で、全機能の使い方と量子計算の説明を開けます。目次から各項目へ移動でき、「閉じる」またはEscapeでメモへ戻ります。メモの編集状態や回路の設定は保ちます。[単独で読めるヘルプのHTML](HELP.html)も用意しています。ダウンロードしてブラウザで開けます。

ヘルプ本文は `src/help-content.html`、共通の表示は `src/help.css` で管理します。`npm run help:export` または `npm run build` で、同じ本文から `HELP.html` を生成し、目次のリンク先も検証します。

- 一覧はタイトルのみを表示します。メモを選ぶと本文は伏せた状態になります。
- 「量子検索」1回で回路の計算と測定を行い、測定されたメモの本文を開きます。そのまま編集できます。
- 測定位置の初期値は最後です。変えたい場合だけ「回路と状態」を開き、スライダーを調整します。回路図と振幅・確率の表は一緒に表示します。
- 途中で測定すると、目標以外のメモや空き状態が出ることがあります。別のメモの場合は、そのメモを選択して本文を表示します。結果は成功で置き換えません。
- 観測後やメモの選択時には測定位置を最後に戻します。詳細欄は次の観測に使う回路と測定前の状態です。
- 広い画面では左にメモ、右に回路・計算を並べ、それぞれ独立してスクロールします。狭い画面では上部の「メモ／回路・計算」で切り替えます。本文の下までスクロールする必要はなく、切り替えても編集中の内容・回路の開閉・測定位置を保ちます。「量子検索」などの操作ボタンは両方の欄で画面上部に残ります。
- 「新規」で作ったメモはすぐに書き込めます。「本文を伏せる」や他のメモの選択で本文を閉じられます。
- 削除直後は「元に戻す」で復元できます。タイトルの絞り込み、JSONの書き出し・読み込みに対応します。
- 「複製」1回でタイトル・本文を量子テレポーテーションで転送し、完了後に「○○のコピー」を保存順で元のメモのすぐ後へ追加して開きます。表示順は通常・休眠寄りの仕分けに従います。元のメモは変更しません。本文が伏せた状態からも使えます。最大128件に達すると複製できません。
- 「おまかせ」1回で量子ウォークを計算し、現在以外のメモを1件測定して本文を開きます。2件以上で使えます。「おまかせの詳細」で、実行済みの回路、各段階の複素振幅・確率、実際の測定結果を一緒に確認できます。開閉状態は連続実行でも保ちます。
- 本文を「量子検索」や「おまかせ」で開くと、そのメモの通常／休眠状態も1回測定します。時間に応じたRx回転と測定によるゼノン効果を計算し、一覧では休眠の確率が50%を超えるメモを「休眠寄り」として下へまとめます。詳細に実際の振幅・回路・測定結果を表示します。
- コピーは通常どおり即座に行えます。このメモ帳のタイトル・本文へペースト（Ctrl+V、右クリックの貼り付けなど）すると、その文字列を量子テレポーテーションで転送し、完了後に復元した文字列を挿入します。「貼り付けの詳細」を開くと回路と実際の測定結果を確認できます。追加の実行ボタンはありません。
- 選択したメモと他のメモを自動でSWAPテストにかけ、「似たメモ」を1件だけ表示します。編集が600 ms止まると再比較します。候補を押すとそのメモを選択し、本文は伏せたままです。「比較の詳細」に回路と実際の測定回数をまとめています。

ブラウザ版はlocalStorage、Android版はアプリ専用のSharedPreferencesに自動保存します。サーバーやGitHubには送信しません。GitHubに保存するのはプログラムです。保存キーと既存の項目は以前の版と同じで、既存のメモを引き継ぎます。追加の任意項目`zeno`に測定後の基底状態と基準時刻を保存します。ブラウザとオリジン（ホスト・ポート）が違うと保存領域も異なります。ブラウザのデータを削除する前に、必要なメモをJSONに書き出してください。

## 量子計算

計算部分は画面から独立した `src/quantum/simulator.ts` にあります。Qiskitや量子実機は使用していません。

1. メモ数Nに対して `ceil(log2(N))` 量子ビットを用意します。
2. 実部・虚部を持つ状態ベクトルにHゲートを適用し、一様な重ね合わせを作ります。
3. 選んだメモの番号を印付けするオラクルと拡散回路を、H・X・多重制御Xで構成します。
4. 指定した位置までのゲートを適用した状態の確率から、1回だけ測定します。初期値の最後まで進めると、最初の成功確率の山に達します。

拡散回路は標準の演算子の負号付きです。グローバル位相を状態ベクトルに保持します。確率は複素振幅の絶対値の2乗です。途中状態の参照は測定ではなく、測定は「量子検索」を押したときに行います。測定には `crypto.getRandomValues` の古典的な乱数を使います。

| メモ数 | 基底状態数 | 最後までの増幅回数 | 目標の測定確率 |
| --- | --- | --- | --- |
| 1 | 1 | 0 | 100%（量子ビット不要） |
| 2 | 2 | 0 | 50% |
| 3〜4 | 4 | 1 | 100% |
| 5〜8 | 8 | 2 | 約94.53% |
| 9〜16 | 16 | 3 | 約96.13% |
| 17〜32 | 32 | 4 | 約99.92% |
| 33〜64 | 64 | 6 | 約99.66% |
| 65〜128 | 128 | 8 | 約99.56% |

候補数は次の2のべき乗に切り上げ、余った基底状態は空き状態として扱います。最大128件です。シミュレーションによる検索の高速化は目的としていません。

## 貼り付けの量子テレポーテーション

貼り付けイベントの既定処理を止め、イベントで受け取った文字列をインラインのWeb Worker内で全ビット転送します。転送が完了するまで編集欄の内容は変えません。受信側の測定結果から復元した文字列で、ペースト開始時の選択範囲を置き換えます。先に元の文字列を挿入することも、エラー時に元の文字列で代用することもありません。

処理中は「転送中」と進捗を表示します。他の操作や通常のコピーは続けられます。転送中にメモを編集した場合は、待機中の貼り付けを中止し、編集内容を優先します。再度のペースト・別のメモの選択・本文の非表示でも前の転送を中止します。タイトルは改行を除き、本文は改行コードをLFに揃え、文字数上限に入る部分だけ転送します。

クリップボードを書き換える処理はなく、コピー操作も変更しません。貼り付けイベントで受け取ったテキストだけを使います。他のアプリや文書でコピーした内容を、後からこのメモ帳が上書きすることはありません。他のアプリへのペーストは通常の動作です。

文字列をUTF-16の16ビット単位に分け、各ビットに新しい3量子ビットを用意します。q0に入力ビットを準備し、q1へのHとq1→q2のCNOTでもつれを作ります。q0→q1のCNOT、q0へのH、q0・q1の部分測定を実際に状態ベクトル上で計算します。測定値m1に応じてq2へX、m0に応じてZを適用し、q2の測定結果から文字列を再構成します。既知のビットを転送する用途ですが、実装は複素振幅を持つ任意の1量子ビット状態にも対応し、テストで位相の復元も検証します。

詳細は直近の貼り付けの実行記録です。ビット番号を選ぶと、そのビットの入力、実際のm0・m1、適用した補正、受信結果を同じ回路上で表示します。全ビットについて4通りの途中測定の回数も表示します。詳細を開き直したりビット番号を変えても再測定はしません。別のメモの選択・本文の非表示・ページの再読み込みで記録を消し、保存データやサーバーへ送信しません。

量子実機・量子通信は使わず、測定の抽選にはブラウザの暗号学的乱数を使います。

[Quantum teleportation — IBM Quantum](https://quantum.cloud.ibm.com/learning/en/modules/computer-science/quantum-teleportation)

## メモ自体の複製

「複製」では、タイトルと本文をJSONの2要素配列として1つの文字列にまとめ、その全ビットを貼り付けと同じ3量子ビットの回路で転送します。測定結果から復元した配列を読み込み、新しいID・更新日時・「のコピー」を付けたタイトルで別のメモを追加します。本文は改行や空文字を含めてそのまま維持し、タイトルは入力欄の120文字コード単位に収まるよう調整します。

計算が終わるまでメモの件数は増やしません。転送中に編集・別のメモの選択・新規作成・削除・量子検索・本文の非表示を行うと、未完了の複製を中止します。「複製の詳細」で実際の回路、各ビットの測定・補正、全体の測定回数を確認できます。クリップボードは使いません。

「複製の詳細」は複製前から開けます。開閉状態は複製の開始・進捗・完了やメモの切り替えでも維持し、計算中は同じ欄に未測定の回路を表示します。「表示する転送記録」の番号は、全文を0/1に分けて転送した結果のうち何番目を見るかを選ぶ表示操作で、複製の設定ではありません。変更しても再計算や複製内容の変更は行いません。貼り付けの詳細も同じ表示です。

## 似たメモのSWAPテスト

タイトル・本文から文字の特徴を作る部分は古典的な前処理です。NFKC正規化・小文字化の後、文字・数字・記号の連続部分から隣接する2文字を取り出します。1文字だけの語は1文字の特徴とし、空白・句読点・タイトルと本文の境界をまたぎません。出現頻度の対数と文書頻度でTF-IDFの重みを付け、64件までは64次元、65〜128件は128次元の共通の特徴を使います。各メモから優先する上位特徴の数はmin(4, floor(次元数 / メモ数))です。少なくとも1つずつを優先し、残りの枠を全体の重みで埋めます。ハッシュによる特徴の衝突はありません。上限を超えた特徴は省略し、その件数を詳細に表示します。全ての比較で同じ基底を使い、重みベクトルをL2規格化します。空の特徴から量子状態を捏造することはせず、そのメモは比較対象から外します。

64次元では各6量子ビット、128次元では各7量子ビットの振幅として、二分木状の制御Ryゲートで実際に準備します。独立に準備したA・Bの状態をテンソル積にし、|0⟩の補助ビットを加えた13または15量子ビットの複素状態ベクトルにH、6または7組の制御SWAP、Hを適用します。比較結果を内積の解析式で代用しません。

回路の最終振幅から補助ビットの測定分布を計算し、ブラウザの暗号学的乱数で各候補4,096ショットを独立に抽選します。これは各ショットで同じ入力を準備する場合のシミュレーションで、1回の測定後の崩壊した状態を繰り返し測る処理ではありません。分布は一度計算して再利用し、同じ回路を4,096回再計算する必要はありません。結果の0の回数をn0とし、`max(0, min(1, 2*n0/4096 - 1))`を重なりの二乗の推定値として使います。順位はこの測定推定値だけで決め、10%以上の最上位を1件表示します。同点はメモの一覧順です。測定にばらつきがあるため、近い候補は再比較時に入れ替わることがあります。特徴の一致に基づく目安で、意味の理解・一致率や検索の高速化を主張するものではありません。

計算はインラインWeb Worker内で行います。編集・選択変更・削除・複製などで入力が変わると、古い計算を停止し、遅れて届く結果を無視します。詳細を開閉するだけでは再測定しません。比較の記録は永続保存せず、サーバーやGitHubにも送信しません。通常画面と詳細のどちらにも本文の抜粋や特徴の文字列を表示しません。タイトル・本文の保存形式は変更しません。

[Quantum fingerprinting / SWAP test — Buhrman, Cleve, Watrous, de Wolf](https://jhwatrous.github.io/BuhrmanCleveWatrousdeWolf2001.pdf)

## おまかせの量子ウォーク

一覧順のメモN件を輪に並べ、現在のメモを出発点にします。位置は `ceil(log2(N))` 量子ビット、コインはq0の1量子ビットです。出発点の基底状態と、H・Sで作ったコイン `(|0⟩ + i|1⟩)/√2` を準備します。1歩を `H → S+ → H → S−` とする2段階のコイン付き量子ウォークで、S+はコイン1の成分だけ右隣へ、S−はコイン0の成分だけ左隣へ移動し、他の成分は留まります。先頭と末尾をつなぎ、Nが2のべき乗でない場合の未使用位置は恒等操作とします。各移動は複素振幅の可逆な置換です。

歩数は `max(3,N)`。途中では測定せず、状態ベクトルへのHと条件付き移動を繰り返し、経路間の干渉を保持します。本文やSWAPテストの類似度は使いません。「次のメモ」を必ず開くため、ウォーク後に出発点の成分を除き、残りの振幅を正規化します。この候補調整はユニタリなウォークとは別の選択ルールで、詳細に明示します。その分布からブラウザの暗号学的乱数で位置を1回測定します。結果を見て引き直す処理はありません。測定後も、その位置に条件付けたコインの複素状態を保ちます。2件なら次の候補は1件なので、そのメモに確定します。

「おまかせ」は測定されたメモの本文を直接開き、タイトルの絞り込みを解除します。未完了の複製や、移動前のメモへの未完了の貼り付けは中止します。計算は最大8量子ビットの小さな状態で同期的に完了し、人為的な待ち時間やアニメーションを入れません。本文やメモ件数は変更しません。

詳細は直近の実行記録です。初期状態、各H・移動、候補の調整後、最後の測定後までを「表示する計算段階」で参照できます。初期表示は測定直前です。スライダーは記録の表示だけで、次の計算や測定位置を設定しません。元の分布と出発点を除いた分布を区別し、実行時のタイトルと順序、測定番号を保持します。メモを編集・選択・削除しても過去の記録を新しい一覧で置き換えず、次の実行で更新します。詳細の開閉・ヘルプ表示では再測定しません。記録は永続保存せず、読み込み直すと消えます。

[Discrete-time quantum walk — Childs, chapter 18](https://www.cs.umd.edu/~amchilds/qa/qa.pdf) / [Split-step construction — Kitagawa et al.](https://arxiv.org/abs/1003.1729)。本アプリのHコイン・有限の輪・歩数・出発点の除外はアプリ独自の選択です。

## 読書と量子ゼノン効果

各メモを独立した1量子ビットとして、通常を|0⟩、休眠を|1⟩に対応させます。最後の測定・状態準備からの時間Δtについて、`Rx(π * Δt / 24時間)`を複素状態ベクトルに適用し、読む操作で実際に1回測定・収縮させます。確率は振幅から求め、読書回数の加点で代用しません。24時間で通常から休眠、48時間で通常へ戻る周期です。短い間隔で読むと同じ状態にとどまりやすく、休眠側でも同じ抑制が起こります。編集すると通常に準備し直します。

一覧は休眠の確率が50%を超えるかで安定に2グループへ仕分けます。これは測定とは別の表示ルールです。各グループ内は保存順を保ち、本文・ID・更新日時を変えません。メモの選択・作成・編集・削除・復元・読書・複製完了・再読み込み時に更新し、タイマーで一覧を動かしません。検索とウォークには実行時の全メモの表示順を渡し、記録にはその時点の順序を保持します。タイトルの絞り込みはこれらの候補数を減らしません。

測定後の状態と基準時刻をメモに保存し、古い保存データは導入時点で通常に初期化します。時計の巻き戻りでは経過時間を0とし、次の測定でも基準時刻を巻き戻しません。保存時には確率に影響しない全体位相を省略します。任意のゼノン項目だけが不正な場合は本文を保ってその項目だけを初期化します。直近の回路記録は保存しません。詳細の開閉や確率の参照で測定せず、本文が既に開いていても検索・おまかせを実行すれば新たな測定になります。新規・複製は通常状態の準備です。

[Quantum Zeno effect — Itano et al.](https://tf.nist.gov/general/pdf/858.pdf)。メモへの対応付け、Rx回転、24時間の尺度、一覧の仕分けはアプリ独自の設計です。

## 検証

## 削除の振幅減衰

「削除」1回で、タイトル・本文のJSON配列をUTF-16のビットに分け、各ビットと新しい環境の2量子ビットを計算します。制御Ry(π/2)とCNOTによる振幅減衰（γ=0.5）を適用し、環境を測定します。1が残れば新しい環境で繰り返し、全ビットの最終測定が0だった場合だけメモを削除します。計算はインラインWorkerで行い、先に削除することも、計算エラー時に通常の削除へ切り替えることもありません。

計算中は「消去中…」。編集・メモの選択などで中止します。1ビット64回の結合でも緩和を確認できなければメモを残します。「元に戻す」は通常の本文・ゼノン状態を別に控えて復元します。安全なデータ抹消や実機の冷却は行いません。

「削除の詳細」は計算欄の先頭です。最後の1件を消しても開いたまま記録を確認でき、各ビットの結合回、実際の環境の測定、各ゲート後の複素振幅、全体で残った励起を表示します。表示操作で再測定しません。各ビットを順番に計算した記録を結合回別に集計し、未測定の理論値と実際の測定軌跡を区別します。

モデル：[Qiskit Aerの振幅減衰チャネル](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.noise.amplitude_damping_error.html)。量子状態は通常のコンピューターでシミュレーションし、サーバーへ本文を送信しません。

## 古いメモの自動堆積

通常メモが32件以上になると、7日間使っていないメモを量子ウォークの対象にします。選択・読書・編集で利用時刻を更新し、選択中のメモは保護します。1日を1歩として、H → S+ → H → S− → 吸収先だけの射影測定を実行します。吸収されたメモを「堆積」1冊へ、タイトル・更新日時・全文を付けて移します。AI要約や文字列の切り詰めは行いません。一度堆積先ができれば、32件未満になっても続きます。

IDのハッシュによる8グループを最大16件ずつに区切り、それぞれに吸収先を加えた輪を作ります。各対象メモを出発点とする独立したウォークであり、本文同士の量子状態を干渉させるモデルではありません。非吸収なら位置を特定せず、残った位置の複素振幅を保存して続きを計算します。構成が変わったグループは現在時刻で再準備します。変わらないグループの位相は維持します。

起動時・1分ごと・画面に戻った時に確認し、各メモ最大30日分ずつ追いつきます。常駐処理は使いません。処理済み時刻と条件付き状態を自動保存し、再起動で同じ日を抽選し直しません。7日経過時が最初の1歩です。アプリの時間尺度は物理的な実時間を意味しません。

取り込みはWorkerの計算完了後に一括反映し、途中で内容が変わった場合は古い結果を反映しません。手動削除・複製中や堆積本文を開いている間は待ちます。取り込み後の「取り込みを戻す」で直近1回分を戻せます。堆積本文がさらに変わった場合や128件を超える場合は復元できません。堆積メモも128件に含み、20万コード単位を超える結合本文を省略しません。

「堆積の詳細」で最後の測定の回路・複素振幅・確率・実測と、直近16回の取り込み履歴を確認できます。履歴・利用時刻・条件付き状態はJSON移行にも含み、複数の堆積先を読み込むと本文を保持して1冊に合わせます。

設定定数は src/sedimentModel.ts、量子計算は src/quantum/sinkWalk.ts、時刻と取り込み処理は src/sedimentation.ts です。参考：[吸収境界を持つ量子ウォーク](https://cs.uwaterloo.ca/~watrous/Papers/AbsorbingQuantumWalks.pdf)。有限の輪とメモへの対応付けは独自設計です。

## 量子誤り訂正つき自動保存

入力が250ミリ秒止まると、保存用JSONの全UTF-16ビットを新しい5量子ビットの回路へ通します。データ3量子ビットを位相反転符号に符号化し、各組で「ノイズなし／q0・q1・q2のいずれかにZ」を等確率で選びます。検査用q3・q4にH・制御X・H・部分測定を実行し、その測定値だけからZ訂正の位置を決定します。復号したq0の最終測定から文字列を復元し、Workerと保存側で全文一致を確認してから復元結果を端末へ書き込みます。既知の入力表や正解文字列のコピーで回路を代用しません。

自動保存の操作は変えず、「訂正中… → 保存中… → 自動保存」と進みます。編集が続くと古い計算を止め、最新の内容を処理します。書き込みは順番を保ち、待機中の古い結果は捨てます。不一致やエラー時に通常の保存へ切り替えず、「未保存」と通知します。長いメモでは時間がかかるため、保存が終わるまで画面を閉じないでください。JSONの書き出しは画面上の内容をそのまま保管できます。

「保存の詳細」で全ビットの測定集計、ノイズと訂正の回数、実際の回路とゲート後の振幅・確率を見られます。詳細用の記録だけを最大256件に抑え、先頭から末尾まで等間隔に選びます。すべてのビットは回路で計算し、記録の参照では乱数を引き直したり保存し直したりしません。メモ本文や保存JSONを詳細へ直接表示しません。

訂正するのは回路内で加えた位相反転で、保存媒体の故障を直す方式ではありません。3量子ビット符号は各組の単一位相反転を対象とし、一般の複数誤りに対応するとは主張しません。量子計算は src/quantum/errorCorrection.ts、Workerと保存の境界は src/quantumSave.ts と src/useQuantumSave.ts です。

参考：[IBM Quantum Learning — Repetition codes](https://quantum.cloud.ibm.com/learning/en/courses/foundations-of-quantum-error-correction/correcting-quantum-errors/repetition-codes)
